# LLM Bot — Мониторинг LLM-сервера в Mail.ru MyTeam

Бот для канала Mail.ru MyTeam (VK Workspace), который выполняет фоновый мониторинг LLM-сервера (llama.cpp) и предоставляет интерактивные команды для проверки состояния в реальном времени.

## Возможности

### Фоновый мониторинг
- **Health Monitor** — периодическая проверка доступности LLM-сервера через endpoint `/health`. При изменении состояния (доступна/недоступна) бот автоматически отправляет уведомление в канал.
- **Metrics Monitor** — периодический опрос endpoint `/metrics` для отслеживания загрузки LLM. Бот определяет состояние занятости (свободна/занята) на основе метрики `llamacpp:requests_processing` и отправляет уведомления при смене состояния.

### Интерактивные команды
Бот отвечает на команды, отправленные в канал:

| Команда | Описание |
|---------|----------|
| `/status` | Текущий статус занятости LLM (занята/свободна/неизвестно) |
| `/tokens` | Скорость обработки токенов (prompt и generation tok/s) |
| `/model` | Название загруженной модели |
| `/context` | Размер контекстного окна модели |
| `/health` | Статус здоровья LLM-сервера (доступен/недоступен) |

## Требования

- **Python 3.10+** (рекомендуется 3.12+)
- Доступ к API Mail.ru MyTeam для ботов
- Рабочий LLM-сервер (llama.cpp) с открытыми endpoints `/health`, `/metrics`, `/models`

## Установка

1. Клонируйте репозиторий:
```bash
git clone <repository-url>
cd llm-bot
```

2. Создайте виртуальное окружение:
```bash
python -m venv venv
source venv/bin/activate  # Linux/macOS
# или
venv\Scripts\activate     # Windows
```

3. Установите зависимости:
```bash
pip install -r requirements.txt
```

4. Создайте файл `.env` на основе шаблона:
```bash
cp .env.example .env
```

5. Заполните переменные окружения в файле `.env` (см. раздел "Конфигурация").

## Конфигурация

Скопируйте `.env.example` в `.env` и заполните необходимые значения:

| Переменная | Обязательная | Описание | По умолчанию |
|------------|:---:|----------|--------------|
| `BOT_TOKEN` | ✅ | Токен бота (получается при создании бота в Mail.ru MyTeam) | — |
| `CHANNEL_ID` | ✅ | ID канала (stamp), куда бот отправляет сообщения | — |
| `LLM_API_URL` | | Base URL сервера llama.cpp | `http://192.168.1.35:5003` |
| `HEALTH_CHECK_INTERVAL` | | Интервал опроса `/health` в секундах | `30` |
| `METRICS_CHECK_INTERVAL` | | Интервал опроса `/metrics` в секундах | `10` |
| `STABILITY_TIMEOUT` | | Таймаут стабильности в секундах (ожидание перед уведомлением "LLM свободна") | `10` |
| `COOLDOWN_PERIOD` | | Кулдаун для повторных сообщений о недоступности в секундах | `300` |
| `HTTP_TIMEOUT` | | Таймаут HTTP-запросов в секундах | `5` |
| `HTTP_RETRIES` | | Количество попыток HTTP-запроса | `3` |
| `DRY_RUN` | | Режим тестирования: `1` — только логирование, `0` — реальная отправка | `0` |

## Запуск

```bash
python main.py
```

Бот запустит три параллельных процесса:
1. Long polling для обработки входящих сообщений из канала MyTeam
2. Health Monitor для проверки доступности LLM-сервера
3. Metrics Monitor для отслеживания метрик загрузки

Для остановки нажмите `Ctrl+C`.

## Архитектура

Приложение построено на `asyncio` с параллельными задачами:

- **Bot Client** работает в отдельном потоке (long polling через SDK mailru-im-bot) и передаёт входящие сообщения в asyncio event loop
- **Health Monitor** периодически опрашивает `/health` endpoint LLM-сервера и уведомляет канал о смене статуса доступности
- **Metrics Monitor** опрашивает `/metrics`, парсит Prometheus-метрики llama.cpp и определяет состояние занятости через state machine
- **Command Router** диспетчеризирует входящие команды (`/status`, `/tokens` и др.) на соответствующие обработчики
- **State Manager** хранит актуальное состояние LLM (занятость, метрики, здоровье) и предоставляется всем компонентам
- **Channel Sender** отправляет сообщения в канал с дедупликацией (не отправляет одинаковые сообщения подряд)

## Режим Dry Run

Для тестирования без отправки сообщений в канал установите `DRY_RUN=1` в файле `.env`. В этом режиме все сообщения будут выведены в лог, но не отправлены в канал.
